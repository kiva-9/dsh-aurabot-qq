# Aurabot 使用手册 · 2.0.0-rc.1

Aurabot 在 DSH 里运行，经 SnowLuma 连接机器人 QQ。操作入口是 DSH 侧栏的 **Aurabot**。这是候选版本，已有本地测试和部分真实服务样例；最终整合包的安装、UI 与验收结果由主线程另行汇总。请先备份，再使用隔离配置试运行。

本次本机整合记录（2026-10-29，以下真实结果由主线程确认）：独立全量备份验证成功；DSH 中间安装包通过 `Magpie/workbuddy-ai/deepseek-v4.1-flash` ping 与专用 system 回合，真实 SnowLuma 连接成功，文本与生图在主人私聊获得 confirmed delivered 回执。Cloudflare BGE-M3 真实中文样例 3/3 及向量范围/删除闭环、GRSAI 生图与参考图再生成已测。StepFun TTS 文件可解码且非静音，**音频可懂性尚未验证**。这些结果只覆盖上述中间包和样例，不代表最终整合包、所有协议或其他用户旧库已通过；金额仅按提供方实际返回记录。

## 第一次设置

1. 在「连接」核对**机器人账号**和**主人账号**，机器人使用独立小号。自行安装 SnowLuma，阅读并同意协议，填入实际目录。
2. 按向导检查、启动网关，登录机器人 QQ 后接入。接入后核对网关返回的登录账号，不要仅凭进程名称判断成功。
3. 在「权限」配置允许的私聊和群聊；在「模型」选择聊天模型。主人私聊权限可选择完整、社交或仅聊天，完整模式可能使用本机工具。
4. 保持**试运行开启**，按需打开总开关，用白名单账号发一条消息，在日志中看处理结果。高层 QQ 发送会受试运行限制，但模型推理、显式提供方测试和可信扩展的直接调用仍可能有费用或外部效果。
5. 核对账号、白名单、模型、任务与诊断后，再自行关闭试运行。总开关关着也不能替代对扩展代码和显式服务测试的检查。

「扩展」里的模块开关与功能页里的业务开关是两层。模块加载成功，只代表代码已运行；外部服务仍可能未配置或未探测。模块关闭时，对应功能页可能隐藏。

## 日常入口

| 要做的事 | 在哪里 |
| --- | --- |
| 暂停自动聊天 | 关闭总开关；正在进行的任务还应在「任务」查看和取消 |
| 更换人设 | 「人格」编辑草稿、发布后绑定到聊天；可先预览当前解析结果 |
| 调整插话 | 「聊天」调整全局或指定群策略；白名单、限流和闭嘴状态仍生效 |
| 给不同聊天选模型 | 「模型」设置私聊/群默认或指定聊天；未配置或模型不可用时按层级回落 |
| 查看事实与来源 | 「记忆」先应用范围，再进入事实、人物画像、待复核或召回记录 |
| 调整当前聊天心情 | 「心情」选择聊天与人设，查看历史、填原因调整或恢复基线 |
| 审核表达和黑话 | 「表达与黑话」选择范围和类别，查看来源后审批 |
| 检索历史事实或图片 | 「检索与索引」配置并保存，按需探测，然后在工作台查询 |
| 管理表情 | 「表情包」选择聊天，审核素材、查看分析与 QQ 同步状态 |
| 观察后台工作 | 「任务」查任务/等待；「诊断」看账本、Hook、迁移和错误 |
| 改模块 | 「扩展」开关、fork 或恢复内置版；自定义代码不是沙箱 |

全局设置卡通常修改后要点页面底部**保存**；事实编辑、审核和任务按钮提交的是单次操作。出现版本冲突时先刷新重新核对，不要连续重复提交旧表单。

## 记忆：先选范围，再看事实

「查看范围」中的机器人账号来自当前配置。聊天填写 `private:QQ号` 或 `group:群号`，点**应用范围**后再操作。

- **普通人物事实的人设 ID 留空**。这里的“公共事实”仅指同一授权范围内不限定人设，不是全局公开。
- 角色经历或人设对应的画像可填人设 ID，或点“使用此聊天当前人设”。当前人设能看到本范围通用事实和自己的限定事实。
- 账号之间不能共享。共享组必须明确列出聊天和类别；共享不传递，也不授予接收聊天编辑权限。由多个来源推导出的内容只有全部证据都允许当前查看者读取时才可见。

### 新增、编辑与更正

在「事实」点**新增人工记忆**，填写完整表述、事实主体、说话人、属性/关系和值，再选择肯定或否定、断言/转述/计划/玩笑等模态、稳定程度、条件和时间。主体与说话人不一定是同一个人；转述、猜测和计划不能自动变成稳定事实。

填写**复核依据**和**操作原因**，只记录确实核实过的材料。条件为空和条件未知含义不同，时间不清楚可保持未知，不要补造日期。保存后查看来源和审计记录。编辑时系统检查版本；更正可保留新旧事实的替代关系，撤回保留历史。

「人物画像」按身份、关系、稳定事实、偏好、近期互动、不确定项组织内容，可重建并保存有证据支持的人工覆盖。覆盖记录有独立版本；源事实改变、删除或变得不可见后，旧覆盖文本会隐藏，不能靠旧画像继续泄露证据。

### 删除和恢复

删除会留下阻止重新出现的记录，不能靠迟到的模型回答自动复活。

1. 在「待复核」找到删除项并申请恢复；这一步仍不进入自动聊天记忆。
2. 查看来源审核，逐项核实证据仍存在、内容未变化、范围正确，再批准相应证据。
3. 证据全部符合要求后，单独批准事实。

原消息已修改、撤回或不存在时，不能照旧批准；应重新核实材料。审计记录用于追溯，不会作为新的自动记忆来源。

### 旧档案与增量提炼

库旁或 legacy/ 中的旧 memories.json 会按来源自动隔离导入一次，原文件保留。到「待复核」打开**包含范围未知的旧档案**查看。读取失败会保留待处理错误，不能当作已迁移成功。手动粘贴旧笔记或 JSON 也只进入隔离区，需要确认目标范围并填写核实后的事实与证据。

默认满足 **20 条新消息或 30 分钟时间条件**后尝试增量提炼，而且必须有新消息；这不是固定每半小时成功完成的承诺。面板显示“已处理”“接收至”和错误；成功事务才推进处理位置，失败区间留待重试。点击**提炼当前范围**可能调用记忆模型并产生费用。

不再执行“每日整理后清空原日志”。消息、证据和处理位置保留供追溯；当前还没有自动清除全部原始记录的承诺。面板列表、词法候选和统计有数量边界，查不到旧条目不一定说明数据丢失；大历史枚举需分页接口或后续检索流程。

## 心情、表达与黑话

**心情**按机器人账号、聊天、人设隔离。默认关键词判断，模型判断开关默认关；基线 60、半衰期 3 小时。面板可查看变化、填原因微调或恢复基线。心情只轻微影响语气和表达，不应拒绝明确请求、澄清或已承诺任务，也不会改写事实、身份或权限。

**表达与黑话**将“学习”与“使用”分开：默认两者都关闭，私聊学习也默认禁止。开启前先选好聊天与当前人设，保存设置。

- 表达习惯和黑话词典是不同类别，来源消息可在面板选择和核对。
- 自动学习产物先待审，人工条目也需要来源；审核后还要开启“使用”才会进入相应上下文。
- 修改条目、批准、禁用、删除、恢复或回退都会核对版本。恢复回到待审，不直接重新使用。
- 黑话含义可以未知或不确定，不能把猜测当确认含义；隐私、攻击、稳定身份和权限指令不应被学习成表达风格。

## 检索与索引

默认 **retrieval.enabled=false**，文本、图片、联合向量角色初始未配置。即使只启用词法检索，也要核对工作台范围。

1. 在「检索与索引」选本地 SQLite worker 或 Qdrant；配置所需角色的端点、模型、空间、维度、前缀和预处理，先保存。
2. 查看“当前可用能力”。点**探测已配置模型（调用服务）**才会发探测请求，可能收费；启动或热重载不会自动替你探测付费模型。
3. 探测通过后查看同步队列，或由主人发起**当前账号完整重建**。重建会枚举该账号的来源范围及已有索引引用，包含其他聊天和已删除来源的旧范围，不能把当前聊天选择器理解为重建边界。任务登记成功不等于索引已完成；失败、需要重建、来源过多应按实际状态处理。
4. 在工作台选事实或历史图片并查询。图片命中会显示出现记录和来源作者；“作为生图参考”只传递引用，生图提交还会再核验。

文本、图片、联合空间不是互相通用的模型。联合文字搜图需额外对齐样例和探测通过，不能因为向量维度一样就启用。不可用时可降级为词法，并显示原因；候选截断不是“搜索了全部历史”。普通事实可用记忆词法检索，不必配置向量服务。

同一图片文件在两个聊天出现，不代表两个来源都可见。历史图按具体出现记录授权，普通请求不能借其他人的图片身份。相似度也不证明图片中人物就是某个特定人。

重建可能进行提供方探测和编码并产生费用，查询仍按当前查看范围过滤。空间包含其他账号、完整范围超过上限或来源持续变化时会拒绝发布不完整的新代际，保留原代际；不要用某个聊天的局部数据替换账号完整索引。

## 表情包

先选择聊天，再查看待审、已批准、拒绝、禁用、删除或旧库隔离项。可以上传或收集表情、改名字和标签、查看分析及来源；旧库未知范围项先分配到本聊天待审区。

**本地保存、分析成功、审核批准、QQ 收藏成功是四件不同的事。** 日常回复只选当前可见且用途合适的已批准素材，没有合适项可以不发。动画必须查看原文件再确认，模型关键帧描述不能代表整段动画。素材满额后停止接收，不自动清掉已审核表情。

同步队列显示 failed 时先看原因；unknown 表示可能已在 QQ 执行。先在 QQ 核对，再按实际情况点“核对已执行”并填写收藏 ID，或确认确实没执行后选“核对未执行”。不要把超时直接当成没收藏再点一次。

## 生图、语音、搜索与任务

生图、搜索、翻唱和 B站业务默认关闭。生图页可配置 OpenAI 兼容、Gemini、ComfyUI 或固定 HTTP 协议，但支持的文生图、图生图、编辑、蒙版、多参考等能力取决于具体 profile 与适配器交集。先保存再测试，显式测试也可能收费。历史图片和搜索候选成为参考图前需要对应来源复核。

语音默认 provider 为 none：需要自己配置外部 OpenAI 兼容 TTS、固定 HTTP 映射，或显式开启本地脚本。不再内置 edge-tts 或 Windows 语音安装/回退。没有配置或明确失败时可能回落文字；已经发送但结果未知时不会自动补一遍文字。语音识别还依赖网关或 DSH 提供的实际能力。

在 DSH「插件」启用语音输入并准备模型后，语音页显示当前识别状态。“上传音频识别”复用已有录音，只调用所选 DSH 识别服务；“合成一句再识别”还会调用保存的 TTS 服务。上传上限 20 MiB、120 秒，压缩音频需要本机 FFmpeg；结果在面板显示。QQ 入站优先调用 QQ 自带转文字，失败再使用 DSH 识别。

「任务」统一查看已登记的生图、翻唱与等待；选择聊天后刷新。常见状态：

| 状态 | 含义 / 操作 |
| --- | --- |
| queued / preparing / waiting_input | 排队、准备或等待属于该请求的输入 |
| submitting / running | 已进入提交或运行，取消不保证服务未收费 |
| generated / delivery_pending | 结果已生成或待投递，尚不能说 QQ 已收到 |
| delivered | 当前账本已有送达依据 |
| cancel_requested / canceled | 取消处理中 / 本地任务已取消，不承诺退款或撤回已送达消息 |
| failed | 明确失败；先看失败依据和重试条件 |
| unknown | 可能已收费或送达，禁止盲目重交、重新生成、补发 |
| 等待已唤醒或过期 | 等待条件满足或超时；不等于被等待任务成功 |

`qq_wait` 登记带期限的等待并结束当前决策；`qq_stop` 只停止当前决策，不取消后台任务；`qq_cancel_task` 才取消指定任务或等待。取消等待不会取消它等待的生图/翻唱。重启恢复只会按账本推进可确认安全的步骤，未知结果需先查提供方或网关回执。

## 诊断：用量、只读回放与延迟

在「诊断」选择聊天并刷新，查看请求链路、决策和 QQ 回执。**模型与服务用量**卡按当前账号/聊天展示调用，选中请求后可切换“仅所选请求”。账本只保留标识、服务/模型、角色、状态、耗时和数值用量，不保存提示词、回复正文或完整提供方响应。

tokens、credits、amount 只按服务实际返回登记，缺失显示“未提供”或 null，不能当作 0 元或免费；credits 也不自动换算成货币。金额按 currency 分组，不跨币种相加。计费状态 charged 不能推出具体金额，生图/翻唱尝试即使已知执行状态，未拿到金额时仍记金额未知。共享批次可以关联多个请求，但总账只计一次；分别查看请求后不要再次把共享调用相加。后台调用可能没有单个 requestId，未接入账本的调用也不能假定不存在。

点击请求或决策的**只读回放**，查看当时保存的输入、版本和随机值。只有历史快照完整且纯群聊基础策略版本匹配时才重算这一部分；它不会重跑模型、工具或 QQ，也不会用现在的配置/记忆补造历史。缺失快照、未知 Hook 输入或版本不符会明确显示不可重算；附带账本是当前持久状态，不是完整历史状态机。

延迟统计区分接收至首次决策、首次确认回复和最终投递，按本地接收时间与持久事件/回执计算 p50/p95。没有确认回执、任务未完成、读取截断或时间顺序异常时，相关值保持 null，并列出原因及缺失样本数。统计窗口是有界的最近请求，不能解读成所有历史请求的性能或最终成功率。

## QQ 命令

主人可用命令管理所在聊天，是否执行仍取决于当前权限与功能状态：

| 命令 | 用途 |
| --- | --- |
| /silent、/active | 当前聊天安静或恢复 |
| /quiet、/chatty、/normal | 当前群插话策略 |
| /model、/status、/help | 模型、状态、命令帮助 |
| /remember 内容 | 以当前请求来源记入当前范围，不是全局公开笔记 |
| /reset | 重开当前聊天，使旧回合失效；不等于删除记忆 |
| /off、/on | 总开关 |
| /sing 歌名 | 已配置并允许翻唱时登记请求 |

## 扩展与 fork

「复制一份来改」生成数据目录 modules/<原id>/。保留文件夹和模块 id，才会替换内置模块；改名会变成并存模块。插件本身的分叉也保留 dsh-aurabot-qq 包名和 aurabot 挂载 ID，通过原安装位置替换，不要同时跑两套。

复制器的 files 只支持精确文件名，目录和通配符无效。改完核对导出、范围与取消逻辑，再看「扩展」的运行/错误状态。新版内置模块不会自动合并进 fork；“用内置的”可临时恢复。安全模式只停止用户模块加载，不撤回其先前外部操作。

扩展 API 2 提供 prepareContext 异步准备和 context 同步读取。Hook 超时会丢弃迟到结果，但不能强制停止 JavaScript 或已经发出的请求。面板“模拟测试”会运行模块代码；捕获高层发送不代表拦住模型费用、直接 OneBot、文件或网络调用。

## 升级、备份和排错

默认数据目录为 `%USERPROFILE%\.dsh\plugins-data\aurabot\`；设置 DSH_HOME/AURABOT_DATA_DIR 时以实际目录为准。配置、aurabot.db、assets、modules、modules-data、local、日志，以及外置模型/翻唱环境都可能是恢复所需资料。

升级前停止插件，独立复制完整数据目录与外置资源，并保留对应插件版本。自动 `_backup-v2-*` 只备份清单内旧文件和目录，会跳过 local、songs、logs、voice-cache 等标记目录；查看 manifest.json 的 copied/skipped/failed。数据库升级备份只含数据库快照。**这些都不是完整备份。**

主库打不开、结构迁移或必要备份失败时，插件会停止聊天与后台任务并返回错误，而不是绕过账本继续运行。先检查磁盘、权限、数据库版本和备份错误，保留原文件；不要删库、改版本号或反复点收费操作来“试好”。旧库不能直接交给不认识新 schema 的旧版插件。

直接覆盖旧整库会丢失备份之后的删除屏障。仓库提供独立的**离线隔离恢复准备工具**：先停止 DSH 及全部子宿主，再从源码仓库运行；以下是替换路径后使用的模板，不会自动选择用户真实数据目录。

```text
node scripts/restore-aurabot.mjs --current <当前主库路径> --backup <备份主库路径> --output <新隔离目录> --offline
```

`--offline` 是操作者已经停止 DSH 的确认，不是自动进程检测。输出目录必须不存在，且位于两个源数据库目录之外。工具先独立复制当前数据库及 WAL/SHM/journal 并核对哈希，再复制备份，创建 `candidate/quarantined.sqlite`、关闭自动功能的新 `config.json` 和 `report.json`。原库与原备份不被写入或切换；`scripts/` 当前不在安装包的 files 清单中，CLI 从源码仓库使用，程序接口见 [API 文档](../src/modules/API.md)。

候选库合入可核对的事实/证据 tombstone、撤回审计、消息撤回、人设及其他已支持领域的删除记录。恢复的事实与证据需重新分别复核，历史消息保留但不能自动重新提炼为记忆事实，画像/派生缓存失效。旧发送及外部任务不能证明未执行的步骤转为 unknown；不自动重试、补发或推断退款。调用账本保留已记录数值与 null，遇到同一调用 ID 的矛盾记录会拒绝，不能替代提供方对账。

退出码 0 只表示**隔离准备成功**：报告始终为 `switchAllowed:false`、`deletionHistoryComplete:false`，没有 force/install/switch 开关。工具目前支持主库 schema 7 及明确识别的领域结构；损坏、未知表、缺失删除表、身份冲突、源文件变化或无法确认离线条件都会拒绝，保留已有副本和错误报告。当前库已经遗失、被清理或更早回滚掉的删除历史无法凭旧备份找回，因此不能宣称“所有删除都已恢复”。正式切换和重新开放使用仍需独立审核与集成。

这个恢复副本只覆盖主 SQLite 和旁路文件，不是全量备份；媒体、外部向量库、旧 JSON、宿主配置和安装模块没有恢复。数据库快照/审计仍保留原数据库内容，包括可能存在的任务凭据；仅新生成的配置没有复制凭据。审核后的索引需要按来源重建，不能直接启用旧派生库。已验证的独立全量备份应继续原样保留。
