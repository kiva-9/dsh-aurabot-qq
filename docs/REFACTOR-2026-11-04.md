## 1. 已修复

### 1.1 安全边界

- **面板/模块 API CSRF**：`host.js` 的 exact/prefix 路由统一检查 `Sec-Fetch-Site` 与 `Origin`/`Host`，跨站请求返回 403 `FORBIDDEN_ORIGIN`；不改变 DSH 同源面板与本机 CLI/测试调用。
- **`/modules/tool` 默认提权**：不再默认 `as !== 'other'`，必须显式 `as:'owner'` 才使用 owner/full；模拟接口默认按“别人”。
- **生图面板路由**（媒体分支）：
  - `/imagegen/submit` 校验 `imageGen.enabled`、聊天白名单、`ownerOnly/isOwner`；
  - `/imagegen/asset` 按图库/任务归属校验，不能只凭 asset id 读全局资产；
  - `/imagegen/jobs|job|cancel|resend` 按聊天/actor 过滤。
- **SSRF**：生图结果 URL、TTS `json-url`、翻唱下载统一走公网校验/逐跳重定向检查。
- **SnowLuma**：路径前缀改为分隔符边界；stop/dispose 杀进程树并等待；密码明文接口仍保留（见待决策）。
- **危险命令确认**：补充引号、`--`、`/bin/bash`、`env bash`、`chmod -R a+rwx /`、`del /q/f/s`、PowerShell `-EncodedCommand`、`Invoke-Expression` 等规则；仍明确不是沙箱。

### 1.2 配置

- `configRevision` 乐观锁：`/state` 返回版本；`/save` 带旧版本时返回 `CONFIG_CONFLICT`，不再静默覆盖另一个面板/模块的修改。
- 配置坏 JSON：`loadConfig()` 先备份 `config.json.bad-<ts>`，抛出 `CONFIG_UNREADABLE`；`host.apply` 捕获后以默认配置进入只读诊断模式，面板显示 `configError`，禁止保存覆盖。
- section 为 `null`/数组/错误类型不再崩溃：`normalize()` 统一回落到默认对象；补 `test/config-hardening.test.js`。
- 未启动模块的扩展密码不再泄漏：`publicConfig()` 按字段名兜底掩码 `ext`；`mergeFromPanel()` 保存时恢复未改的密钥，避免“保存一次清空”。
- `readBody` 改为 Buffer 合并后一次性 UTF-8 解码，修复跨 chunk 中文/emoji 变 U+FFFD。
- 配置文件写入 `0600`，避免同机其他用户读 API key/Cookie。
- 模块 setup 15 秒超时；清理 drain 15 秒上限，避免坏模块卡死 boot/dispose。
- `voice.enabled`/`stickers.enabled`/`speakUp.enabled` 做布尔归一化（字符串 `"false"` 不再当 true）。

### 1.3 聊天/调度/投递

- `force` **不再绕过 `dryRun`**：试运行时命令回复/模块 force 发送也不会真发；`force` 只在非 dryRun 时绕过总开关。
- 普通回复 outbox 重启恢复：`batchKind/account` 元数据 + sessionReply 安全 guard（account/epoch/enabled/dryRun/request 状态/来源账号）；job 批次仍交给 job worker。
- Scheduler 移除 4 分钟“自动当结束”分支；`busySince` 带 token，`running` 改为 `Map<chatId, turnId>`，迟到 `turn/end` 不能释放新回合。
- 档位/preset 切换统一 `teardownSession`：bump epoch、cancel 旧 agent、unmount、archive、清理 `sessionToChat/turnState/mounted/群状态`；`agentFor`/`switchIdentity`/`resetChat`/`resetSessions`/`abandonChat` 复用。
- `dispatch`/`onMessage` 入库后异常写入站死信，不再永久丢消息。
- `groupInterjects` 确认发送后写入，群聊 cooldown/maxPerHour 不再完全死逻辑。
- `cancelPending` 处理 `sending` 段（标记 cancel_requested，由 transmit 末尾复核）；普通发送前后检查 epoch/signal。
- steer 失败批次回调度器；`groupBuf` 只写白名单群；`groupName` 失败负缓存 60 秒。

## 2. 仍需你决策/后续

1. **多账号数据迁移（D-004）**：`chats` 仍是 `id` 单列主键，多账号共用 `group:xxx` 会污染最近消息/撤回。修复需要 v8 迁移并改 `messages.byPlatformId/recent/markRecalled` 等调用点；默认只跑一个机器人号时可不动。要不要做？
2. **完整 7 页 IA**：当前是 25 个页面按 4 组收敛、当前组只显示 6–8 个，已搬走孤儿设置；没有把所有页面合并成 7 个一级页。完整合并需要重写面板测试和用户习惯，收益是入口更少，成本是一次较大的 UI 迁移。
3. **面板鉴权级别**：当前是 Origin/Sec-Fetch-Site CSRF 防护，依赖 DSH Web 自身访问控制；如果面板会暴露到局域网/反向代理，需要再加 panel token/会话鉴权。
4. **SnowLuma 未核验注入**：当 SnowLuma 只看到一个“认不出号”的 QQ 进程时，仍会先注入再核对（核对失败会撤销/断开）。要更安全可改成“必须手动确认 pid/先关闭其他 QQ”，代价是多一步操作。
5. **dryRun 语义**：现在 `force` 也不能绕过 dryRun（推荐）。如果你希望试运行时主人命令仍真实发送，需要显式改回并写清例外。
6. **可见性统一（D-005）**：`domain.canSee` 与 `memory.visible` 仍是两套；本次只修了 shareGroups.account，完整统一会影响记忆/学习/搜索三个域，需单独迁移测试。
7. **旧代码清理**：`features/companion.js` 旧全局 mood、`persona/personas.js` 旧 Markdown CRUD、`features/*` 兼容 shim 仍在；是否删除取决于你是否还要兼容旧模块/旧数据。
8. **`history:boundary` 清空历史**：目前没有生产写入入口；“重新开始”只归档会话，不删除/屏蔽旧历史。若需要“清空聊天”语义，需要先确定 UI 和删除范围（消息/资产/记忆/outbox）。
9. **SnowLuma 密码明文接口**：`/snowluma/password` 仍返回明文用于面板“显示密码”；本机面板可用，但如果要防本机其他进程，需要改成一次性显示/系统钥匙串。
10. **是否把 `.audit-notes` 原始证据纳入仓库**：目前作为本地审计底稿未提交；报告已引用。

## 3. 迁移与回滚

- `configRevision` 是新增字段，旧 config.json 读取为 0，保存后自动 +1；无需手工迁移。
- outbox 新增 `batchKind/account` 元数据；旧批次缺省按 `sessionReply` 处理，job 批次仍由 job worker 恢复。
- 数据层新增索引/DDL 均为 `CREATE ... IF NOT EXISTS`/兼容 ALTER；`PRAGMA user_version` 仍为 7（没有破坏性 v8）。
- 恢复流程扩展了 `KNOWN_TABLES`；旧备份仍可读，派生缓存会归档后清空。
- 回滚代码不会自动回滚数据；升级前仍应备份 `~/.dsh/plugins-data/aurabot/` 整个目录。
