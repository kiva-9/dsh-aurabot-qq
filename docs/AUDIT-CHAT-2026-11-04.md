## 二、聊天链路体验 / 人格遵循审计

### 已修

1. **一轮多段发言只发最后一段（上游 #205）**——体验影响最大。模型「先说一句 → 调工具 → 再说一句」时，前面那句永远发不出来，用户看到的是回应一句不存在的话，日志也没提示。
   修法（`src/chat/hub.js` `assistant/message`）：按 `(turn, step)` 累加；同一 step 或同一段重复推送只算一次；插过话（steer）之后的新一段覆盖旧段，避免前后矛盾。
2. **卡死回合巡检**：每分钟检查一次，忙超过 10 分钟、**且 DSH 那边的会话确实不在 running** 时，带着当时的令牌放开，并停掉「正在输入」。比原来的 4 分钟一刀切保守：模型真在跑就不放开。
3. **模型内部语法漏到 QQ（上游 #220、#207）**：`<br>` 原样发出；上下文注入的历史编号 `m00879b，…` 被模型抄进正文；想调工具没调时漏出 `</｜｜DSML｜｜ invoke>`。现在 `createReplySource` 入口统一清洗（代码块/行内代码不动，编号只认 5 位以上的行首，不误伤 `m1005` 型号），洗完为空就按沉默处理。
4. **规则里的病句影响人格口吻**：`ownerOnly` 关闭时规则会生成「你会画画：画，用 qq_draw_image 登记后台任务」（persona-audit-20261103 里也提到过）。改为「你会画画：别人请你画时用 qq_draw_image 登记后台任务」，开启时为「你会画画（只给主人画）：…」，唱歌同理。

新增测试：`test/chat-reliability-regressions.test.js`（多段累加、steer 覆盖、busyChats 令牌）、`test/reply-artifacts.test.js`。
全量：1819 tests / 1815 pass / 0 fail / 4 skipped。

5. **规则压过人格 → 风格归人设卡**：`rulesText` 里的纯风格条目（闲聊一到三句、短答放一条、私聊主动接话/别查户口/敷衍就少说、被戳时撒娇吐槽）移出运行规则，改为 `compiler.js` 的 `DEFAULT_BEHAVIOR` / `DEFAULT_STYLE`：卡里对应层为空时才用默认，写了就完全以卡为准；旧版整篇 Markdown 卡原样输出不补。规则只留协议（`|||`、`<voice>`、`<poke>`、工具、安全边界、「没有记录的事不说成一起经历过」）。
   - 修掉的直接冲突：私聊卡要求「一到三条用 ||| 分开」，规则却写「短答尽量放在一条消息里」。
   - 内置卡里重复抄写的表情包协议段删除（只在规则里保留一份）。**数据库里已发布的卡不会被内置更新覆盖**，你线上那几张卡里的这段重复仍在，无害；想删可在面板「人格」页手动去掉。

### 未修，建议后续决定

- **回合异常结束 = 完全沉默**：维持现状（不回兜底话），已与主人确认。

- **steer 覆盖的代价**：插话后第一段被丢弃；如果第一段回答的是另一件事，那件事就没回。与上游 #217 的取舍一致，先保留。
- **「正在输入」只在私聊**，6 分钟自动停；群聊没有任何「在想」的反馈。
- **合并等待**：保持默认 2.5s。它是「最后一条之后停顿 2.5s」，每来一条重新计时，从第一条起最多等 8s（`maxSec`）；私聊里模型想的过程中再来的消息会插进当前一轮（steer），所以等待短一点不会丢话，只是偶尔会「说了一半重说」。如果常看到这种情况，再把 `waitSec` 调到 3.5–4。QQ 网关没有把「对方正在输入」推给插件，没法按真实打字状态动态等待。
