## 0. 一页结论

**总体判断：这个插件不是“烂到不能维护”，但已经到了“每加一个功能，就会多一套状态、多一个入口、多一处重复配置”的临界点。** 目前真正的问题不是单个函数写得差，而是四个“单一事实来源”缺失：

1. **配置没有单一事实来源**：全局 `draft` + 底部保存、Persona 草稿/发布、模块行即时 `/save`、扩展面板即时 `/save`、测试按钮使用“已保存配置”五种写入/生效语义并存。
2. **模块开关与业务开关双轨**：`modules.<id>.enabled` 和 `<feature>.enabled` 是两层；模块一关，标签页直接消失，用户无法回到功能页打开业务开关。
3. **会话状态没有单一身份**：会话身份、`running`/`turnState`、outbox 投递状态是三套状态，旧会话/旧回合的迟到事件可以释放新回合、发送旧回复。
4. **前端信息架构没有分层**：25 个一级标签 + 4 个“看起来也像标签”的分组过滤器；多个设置只有一个孤儿入口或完全没有入口。

**如果只修 5 件事，按顺序：**

| 顺序 | 问题 | 理由 |
|---|---|---|
| 1 | 面板 API / 模块路由没有鉴权、没有 CSRF/Origin、GET 有副作用；`/modules/tool` 默认 owner/full | 任意网页或本机进程可改配置、执行 owner 工具；最严重的安全边界问题 |
| 2 | `force` 可绕过 `dryRun`/`enabled`，试运行时仍会真实发 QQ | 直接违背“试运行不真发”的产品承诺；命令回复和扩展发送都受影响 |
| 3 | 会话档位/preset 切换不清理旧 session 映射、旧工具、旧 turnState | 旧回复/旧工具串到新会话，改权限后旧权限仍在 |
| 4 | Scheduler 4 分钟硬超时会启动同一 chat 的第二个并发回合 | 长任务/慢 provider 场景下会混回复、重复发送、丢消息 |
| 5 | 普通回复的 guarded outbox 批次重启后永不恢复 | 半截回复永久 pending；用户只收到半条或收不到 |

**测试基线（不是全绿）：** `npm test` 共 **1745** 个测试，**1738 passed / 4 failed / 3 skipped**。4 个失败中：

- `search-service` 的 1 条在全量并发运行下失败、单独运行通过（测试隔离/时序问题）；
- `vector-retrieval-module` 的 1 条是 macOS `realpath`（`/var` → `/private/var`）断言问题；
- `song` 的 1 条是 Windows 路径/文案断言在 macOS 上不成立；
- `stickers-frames` 的 1 条是系统 ffmpeg 不支持 `webp_anim`。

`node --check` 全部源码通过；仓库没有 ESLint/TypeScript 检查。**不要引用旧文档的“61 项测试通过”作为当前基线。**

### 2.2 分组导航的两个确定 bug

**（1）点分组不切页，内容与标签错位**

```js
// client/client.js:3960
onClick: () => { setNavGroup(g); setNavSearch('') }   // 只改分组
// :3930-3931
const visibleTabs = tabs.filter(... groupOf(t.id) === navGroup)
const curTab = tabs.find(t => t.id === tab) || tabs[0] // tab 仍是旧页
```

例如当前在“语音”（能力组），点“常用”：标签行变成常用 6 页，正文仍是语音页，且没有任何标签高亮。用户会以为 UI 卡住或点错了。

**（2）持久化标签指向已隐藏页面时无回退**

`localStorage.aurabot.tab` 可能是 `voice`，但 voice 模块被关后 `TABS.filter`（`:3927`）已去掉该页；`curTab` 回退到 `tabs[0]`（概览），但 `navGroup` 仍从旧 `tab` 计算（`:3845`），出现“能力组 + 概览内容 + 无高亮”。`ext:old-module` 同理。

这两个问题叠加，是“标签太多太乱、不知道在哪里”的直接技术原因之一。

### 2.5 前端逻辑问题 Top 12

1. **C01 保存/轮询竞态**：`reload` 每 5 秒 `get('/state')`，`save` 成功后 `setSt(r); setDraft(clone(r.config))`；一个早发出的 `/state` 返回可能把刚保存的 `st`/`draft` 覆盖回旧值（`client.js:3859-3892`）。`/state` 本身还会做 SnowLuma 探测、`get_login_info`、`storage.info()` COUNT(*)、`hub.sessions()`，可能耗时数秒。**P1 数据一致性。**
2. **C02 首次向导不可跳过**：`showWizard = !cfg.setupDone || wizardOpen`；`showWizard ? null : 标签页`；Wizard 关闭按钮只有 `setupDone` 才显示；第 1 步 `canNext` 依赖 `sl.installed`（`client.js:3919,3957-3958,3707,3760`）。SnowLuma 下载/检测失败时，连接/人格/权限/模型/扩展全部不可达。**P1 首次体验阻断。**
3. **C03 保存期间继续输入会被回写覆盖**：`save` 取 `body = draft`，等待 `post('/save')`，成功后无条件 `setDraft(clone(r.config))`；输入框没有禁用（`:3881-3890`）。用户点保存后继续打字，刚输入的内容消失。**P1 输入丢失。**
4. **C04 模块开关/安全模式/扩展面板直接 `/save`，之后底部保存会把它们改回去**：`ModuleRow.setMod`/`safeMode`/`ExtPanel.save` 直接 POST；全局 `draft` 仍是旧 `modules/safeMode/ext`，底部保存整份回写（`:3103-3108,3213,3249,3881-3890`）。**P1 配置回滚。**
5. **C05 Persona 未保存编辑不进入全局 dirty**：Persona 自己维护 `dirty`，`TAB_KEYS` 没有 `persona`；切标签无脏点、无提示，关闭面板会丢（`:1208,3937-3941,3967`）。**P1 编辑丢失。**
6. **C06 分组按钮不切页**：见 2.2；**P1 导航状态错乱。**
7. **C07 持久化 tab 指向隐藏页**：见 2.2；**P1 页面错位。**
8. **C08 `bridge` 配置完全无 UI**：`client.js` 全文无 `bridge`；宿主错误却指向“扩展 → 联动”（`host.js:907`）。**P1 功能不可达。**
9. **C09 语音页缺 `defaultVoice`、全局 `speed`、HTTP `apiKey`/`headers`**：配置存在（`core/config.js:85-87`），UI 没有；人格页“留空用语音页默认音色”指向不存在的控件。**P1 功能缺口/文案误导。**
10. **C10 `local.*` 与功能页双闸、状态不随 draft 更新**：`LocalApi` 开关只改 draft，服务端 `x.enabled/x.active` 用于状态文字且只在 mount 拉一次；打开后仍显示“开关没开”；本地 TTS/生图/ASR 还要受 `voice.enabled`/`imageGen.enabled`/`voice.asr` 前置。**P1 状态不一致。**
11. **C11 `TAB_KEYS` 脏标记错**：`group` 漏 `security.dangerConfirm`、`files.*`；`new-features` 包含整对象 `voice/stickers/bili/...`，导致在 Voice/Stickers/Bili 页改任何字段，NewFeatures 标签也亮脏点（`:3937-3941`）。**P2 误导。**
12. **C17 测试按钮与未保存编辑不一致**：ImageGen `ProfileCheck`、Voice 试听、Bili `检查登录`、Song `唱给我听` 直接用已保存配置；Search/ImageJobs 会禁用 dirty。用户改完 API Key 直接“检查配置”，测的是旧配置。**P2 UX。**

| **人格** | 卡片列表、编辑（身份/行为/说话/外观/声音）、参考图、绑定、版本历史 | `persona.*`、`persona.layers.*` |
| **聊天与群** | 权限与名单、群策略、消息合并、会话窗口、附件、跨聊天策略、安全/文件 | `owner*`、`allow`、`profilePerms`、`longTasks`、`group.*`、`merge.*`、`conversation.*`、`incomingFiles`、`ignoredSenderQQs`、`crossChatHistory`、`security`、`files` |
| **能力** | 语音、表情包、生图、联网搜索、主动搭话、翻唱、B站（各一页） | 各功能键；模块开关只做“启用/停用”，业务开关放功能页顶部 |
| **记忆与学习** | 记忆、检索与索引、图片理解、心情、表达与黑话 | `memory.*`、`retrieval.*`、`mediaMemory.*`、`mood.*`、`learning.*` |
| **系统** | 模型与用量、扩展、本地接口、联动、日志、诊断、Token | `model.*`、`chatModels.*`、`roles.*`、`toolCallsPerTurn`、`modules`、`safeMode`、`ext.*`、`local.*`、`bridge.*`、`token-meter`、`diagnostics`、`logs` |

**去重原则：**

1. **每个配置键只有一个 owner 页面**：用一份 `PAGE_DEFS`/schema 声明 `key -> {page, section, label, type, min, max, visibleWhen}`；同一 key 不允许手工出现在第二个页面。
2. **功能页拥有自己的全部设置**：把 B3 的孤儿设置全部搬回所属页（RVC→语音、collectMode→表情、danmaku/vision→B站、ignoreAtOthers/seedHistory→聊天）。
3. **模块开关与业务开关分层但可见**：模块关闭保留标签，显示 `ModOff`（当前组件 `client.js:534-536` 是死代码）；业务页顶部显示“模块未运行 → 去扩展启用”。
4. **多层策略改成三态继承**：`persona.policy.*` 改成 `inherit/on/off`；页头显示“当前有效值（全局/人设）”。
5. **保存统一**：全局 draft + 单一保存条；Persona 的草稿/发布只作为版本管理，不参与全局 dirty；模块/扩展不再直接 `/save`，统一 `commit(patch)`。
6. **测试按钮跟随保存**：所有“检查/试听/测试”在 dirty 时禁用或先保存再测试；由 hooks 统一实现。

**渐进式步骤：**

| 步骤 | 内容 | 风险 |
|---|---|---|
| 0 | 建立 `PAGE_DEFS`/配置 schema（仅元数据，不改 UI） | 低 |
| 1 | 修导航状态：校验 localStorage tab、分组切换自动选首个可见页、模块关闭显示 `ModOff`/`keepPanel` | 低 |
| 2 | 修保存/轮询：请求 seq/Abort、保存期间暂停轮询、Persona dirty 上报、模块/扩展保存并入 draft | 中 |
| 3 | 去重 NewFeatures：孤儿设置搬回功能页，移除重复 SpeakUp | 中 |
| 4 | 页面拆分：Group→群聊/会话/安全，Stickers→图库/审核/设置，ImageGen→服务/任务/图库，Persona→编辑/参考/绑定 | 中高 |
| 5 | 一级 IA 合并为 7 页，旧 tab id 做兼容重定向，移动端抽屉 | 高 |
| 6 | 性能：`/state` SSE/revision、memo 页面、dirty 按字段订阅、`setPath` 不可变路径 | 中 |

## 3. 后端审计

### 3.1 安全边界（最高优先级）

#### S-01 / P0：面板 API 与模块路由没有鉴权、没有 CSRF/Origin、GET 有副作用

**位置：**

- `src/host.js:383-392`：`route()` 直接注册 `ctx.webServer.register`，没有 auth/Origin/method 校验；`answer` 也不校验。
- `src/host.js:543-564`：`/save` 直接 `setConfig(mergeFromPanel(cfg, body))`。
- `src/host.js:885-893`：`/modules/tool` 默认 `as !== 'other'` 即 owner；`level='full'`；`hub.capture` 只截获 `hub.sendText`，不能阻止模块工具直接 `onebot.call`/写文件/改配置。
- `src/core/modules.js:627-631`：模块 `handle()` 只查路由存在、模块在跑，不检查调用者。
- 典型无方法/无鉴权副作用路由：`/bili/run`、`/bili/replies`（`modules/bili/index.js:152-153`）、`/song/install`（`modules/song/index.js:95`）、`/snowluma/start|stop|reset-password`（`host.js:572-600`）、`/test-send`（`host.js:646`）、`/avatar/sync-qq`（`host.js:965`）、`/bridge/token/reset`（`host.js:903`）。

**触发方式（本机/浏览器）：**

- 任意网页可以对 `http://127.0.0.1:<DSH_PORT>/aurabot/api/...` 发起 **simple request**：`fetch(url, {method:'POST', mode:'no-cors', headers:{'content-type':'text/plain'}, body: JSON.stringify({...})})`。`readBody` 不检查 `content-type`，会照常 `JSON.parse`。
- 因此无需读取响应即可产生副作用：改 `enabled/dryRun/ownerQQ`、执行 `/modules/tool` 的 owner 工具、启动/停止 SnowLuma、`/bili/run` 发评论、`/song/install` 安装依赖。
- 若 DSH Web 绑定 `0.0.0.0` 或被反向代理暴露，则变成远程可利用。

**影响：** 配置/凭据/QQ 发送/群管/外部进程都可能被任意网页或本机进程操纵。**P0，先修。**

**修复：** 在 `route()` 和模块 prefix 外统一加 `panelAuth` 中间件（DSH connection admit + 一次性 panel token + Origin/Host 校验 + `content-type: application/json`）；所有副作用只允许 POST；GET 只读；`/modules/tool` 默认 `as:'other'`，owner/full 必须显式重新鉴权；`bridge.token`/`snowluma.password` 改为一次性显示或去掉。

#### S-02 / P1：`/bridge/examples` 与 `/snowluma/password` 明文返回 token/密码

- `host.js:902-904` + `core/bridge.js:260`：`examples()` 把 `getConfig().bridge.token` 拼进 curl/python 示例，且不检查 `bridge.http`。
- `host.js:602-603` + `snowluma/manager.js:490-491`：`/snowluma/password` 直接返回明文 `webuiPassword`；`publicConfig` 的掩码被绕过。
- 结合 S-01，任意本机页面可触发/读取（若同源或 CORS 允许）；至少本地任意进程可读。
- 修复：示例永远用 `<token>` 占位；密码只允许“重置/测试登录”，不提供读取；必须显示时要求主人 QQ 确认 + 短期 token。

#### S-03 / P1：生图面板接口绕过 `imageGen.enabled`、`ownerOnly`、白名单，且资产 IDOR

- `modules/imagegen/index.js:284-320`：`/imagegen/submit` 只校验 `chatId` 正则，不检查 `imageGen.enabled`、`checkAllowed`、`ownerOnly`；`actorId` 固定 owner；`svc.enqueue` 不检查开关；`jobs/image.js:305-311` 直接 `hub.sendImageAssets(job.chatId, ...)`，不重新校验 allow。
- `modules/imagegen/index.js:337-342`：`/imagegen/asset?id=<任意 asset id>` 直接读全局 `storage.assets`；`/imagegen/jobs` 可跨聊天列出任务和 `output.assetIds`。
- 影响：关闭生图后仍可产生费用；可向非白名单群/陌生人发图；可读取人设参考图、私聊图片、其他聊天生成结果（IDOR）。
- 修复：`/imagegen/submit` 校验 `imageGen.enabled && checkAllowed(chatId) && (!ownerOnly || isOwner)`；`/imagegen/asset` 复用 `galleryScope`/job 归属；`/imagegen/jobs` 默认按当前聊天/actor 过滤；面板路由统一 owner 鉴权。

#### S-04 / P1：生图结果 URL、TTS 自定义映射、翻唱下载的 SSRF

- `providers/image/common.js:154-225`：`validateHttpUrl` 只查协议/端口/凭据，`request()` 直接 `fetchImpl` 且默认跟随重定向；`outputFrom()` 对服务返回的 `item.url` 直接 GET（`:443-461`）。
- `voice/tts.js:29-30,209-233`：`fetchBytes` 直接 `fetch(url)`；HTTP 映射的 `json-url` 返回值直接 GET。
- `song/studio.js:741-760`：`fetch(pick.url)` 无 SSRF 检查。
- 影响：恶意/被劫持的生图/TTS/网易云服务可让插件访问本机控制面、云元数据、内网服务；错误信息可能带出响应片段。
- 修复：所有外部下载统一使用 `core/net.fetchImage`/`createSearchHttp`（DNS pinning、私网拒绝、`redirect:'error'`、端口白名单）；对 provider 返回的 `url`/`json-url` 逐跳校验。

#### S-05 / P1：SnowLuma 会把插件注入“唯一一个认不出号”的任意 QQ 进程，再才核验

- `snowluma/manager.js:133-143`：`pickBotProcess` 在只有一个 `account:null` 的 QQ 进程时返回 `{proc, unverified:true}`。
- `:326-355`：`attachBot` 立刻调用 `/api/processes/{pid}/load`；`:358-389` 的 `confirmLogin` 才核对 uin。
- 影响：可能把 SnowLuma 注入主人主号；OneBot 以主号身份连接一段时间；`unload` 不保证成功，最坏需要重启 QQ。
- 修复：只在 WebUI 由用户确认 pid 后注入；或注入前用 `get_login_info`/扫码结果二次确认；`unverified` 路径改为“先让用户关闭其他 QQ 或手工选择”。

#### S-06 / P1：模块 setup 无超时，坏模块会卡死 boot/登录缓冲/dispose

- `core/modules.js:365-372`：`await def.setup(api)` 没有超时；`drainPending` 无限等待 `rec.pending`；`host.js:412-413` 只有 `booted.then` 才 `modulesReady=true`。
- 影响：一个用户模块返回永不 resolve 的 Promise → `modulesReady` 永远 false → 登录缓冲 200 条后丢 QQ 事件；插件退出/热重载 `mods.dispose()` 挂起。
- 修复：setup 设 5–15 秒超时 + `AbortSignal`；`drainPending` 有最大等待；boot 用 `Promise.allSettled` 分批，不因单个模块阻塞全部。

#### S-07 / P1：`danger.js` 是“危险命令确认”而不是安全边界，且只覆盖 `bash`/`pwsh`

- `security/danger.js:11`：`SHELL_TOOLS = new Set(['bash','pwsh'])`；`:16-33` 15 条正则；`:94-113` 无 chatId 时 `next()`。
- 已知绕过（静态判断）：`"rm" -rf /`、`rm -rf -- /`、`curl ... | /bin/bash`、`wget ... | env bash`、PowerShell `-EncodedCommand`、`Invoke-Expression`、`del /q/f/s C:\*`、`chmod -R a+rwx /`、别名/函数/`bash -c "$(base64 -d ...)"`。
- 影响：用户开启“危险命令确认”会误以为有安全边界；实际只防手滑。
- 修复：按工具能力而不是工具名分类；所有可执行命令工具进 guard；用 AST/allowlist；文档明确“不是沙箱”，不要把正则当安全控制。

#### S-08 / P2：`/modules/open` 路径穿越可创建任意目录

- `host.js:836-838`：`const id = String(query(req).id || ''); join(mods.dir(), id)`，`id=../../../../tmp/x` 可逃出；`open-folder.js` 先 `mkdirSync(dir,{recursive:true})` 再打开。
- 修复：`resolve(base,id)` 后校验 `target===base || target.startsWith(base+sep)`；只允许已存在模块目录。

### 3.2 配置子系统

#### C-01 / P1：配置并发保存是整份覆盖 last-write-wins；前端 5 秒轮询会放大

- `host.js:543-549`：`/save` 读整份 body → `mergeFromPanel(cfg, body)`；没有 revision/CAS/串行化。
- 两个面板/快速开关基于同一旧配置保存：后写会把前写改回旧值（本地复现：A 改 `enabled=true`，B 改 `dryRun=false`，最终 `enabled=false`）。
- 前端 `client.js:3859-3892` 的 `/state` 轮询 + `save` 无请求序号，旧 `/state` 响应可回写 `st/draft`。
- 修复：`configRevision` + compare-and-swap（过期 409）；进程内串行队列；前端请求 seq/Abort、保存期间暂停轮询、保存后按 revision 合并。

#### C-02 / P1：坏配置 JSON 静默回默认，下一次保存覆盖原文件

- `core/store.js:22-29` `readJson` 对任何读取/解析错误返回 fallback；`core/config.js:514-526` `loadConfig` fallback `{}`；`saveConfig` 直接 `writeJson(FILE(), c)`。
- 触发：config.json 手工改坏、写入中断、权限临时不可读。影响：全部 QQ/白名单/模型/密钥丢失。
- 修复：区分 ENOENT 与解析/权限错误；解析失败备份 `config.json.bad-<timestamp>`，进入只读降级并告警；禁止自动保存覆盖；保留上一版本。

#### C-03 / P1：`schemaVersion > 2` 在 `apply()` 最前面抛错，插件完全起不来且没有 503 降级

- `config.js:210` 直接 throw；`host.js:63` `let cfg = loadConfig()` 在 storage try 之外；只有 storage 失败有 503 路由（`host.js:94-115`）。
- 触发：先装新版再降级，或手工改高 schemaVersion。
- 修复：把 config 异常纳入与 storage 相同的降级路径，注册只读诊断路由并显示 `configError`；备份原文件。

#### C-04 / P1：`normalize()` 对 section 为 null 直接崩溃（已复现）

- `normalize({model:null})` → `Cannot read properties of null (reading 'vision')`；`{allow:null}`、`{conversation:null}`、`{bridge:null}`、`{bili:null}`、`{voice:{httpApi:null}}` 同样抛错（`config.js:211,217,233,237,241,289-290,342,393`）。
- 触发：手工/旧面板/模块 `setConfig` 把对象写成 null；启动不可用或保存阻断。
- 修复：每个 section 先 `isObj(...) ? ... : {}`；引入 JSON Schema；null 表示 section 默认；补 null 回归测试。

#### C-05 / P1：`publicConfig()` 对未登记模块密码、`httpApi.body`、`extra` 自由字段泄漏原文

- `config.js:530-543` 只按 `allSecrets()` 掩码；`extraSecrets` 只在用户模块 `start()` 时登记（`modules.js:355`）；`startSync` 不登记（`:397-407`）。
- 实测：`normalize({ext:{weather:{apiKey:'TOPSECRET123'}}})` → `publicConfig` 返回 `ext.weather.apiKey` 原文；`registerSecretField` 后才变 `'' + apiKeySet:true`。
- 另：`voice.httpApi.body`（可含 `{apiKey}` 实际值）、`imageGen.profiles[].extra`（ComfyUI workflow/提交 body）不会被 `hideHeaders` 处理。
- 修复：扫描/加载配置阶段就登记所有模块 `settings` 的 password 字段（不依赖启动）；body/extra 做敏感键名白名单或占位符；`publicConfig` 只返回显式安全字段。

#### C-06 / P1：密钥“空串=保留、null=清空”，前端没有统一清除入口

- `config.js:593-601`；面板只有 B 站有“清空”按钮（`client.js:3057`），`voice.openai.apiKey`/`search.apiKey`/`song.neteaseCookie`/`retrieval.*.apiKey` 等只有“留空保留”。
- 影响：用户清空输入框保存后旧密钥继续使用；无法从 UI 撤销泄露的凭据。
- 修复：`publicConfig` 提供 `clearSecrets`/`xxxClear`；每个密钥加“清空”按钮发送 `null`；保存后返回实际清除字段。

#### C-07 / P2：`deepMerge` 让 `modules`/`ext` 对象映射无法删除键；旧设置会复活

- `config.js:591` 深合并；`mergeFromPanel` 只对 `chatModels` 两张表整表替换（`:618-621`），`modules`/`ext` 没有。
- 实测：`mergeFromPanel({modules:{x:{enabled:false}}}, {modules:{}})` 仍保留 `x`；`ext.foo` 只传 `{a:9}` 时旧 `b:2` 仍在。
- 修复：JSON Merge Patch 语义（null 删除、对象替换）；`modules`/`ext`/`tabs` 显式整表替换；提供删除模块设置 API。

#### C-08 / P2：`OPT_IN_ON_UPDATE` 只覆盖“缺失键 + setupDone 为真”，老用户可能绕过默认关闭

- `config.js:511-520`；`setupDone=false` 但有 botQQ/ownerQQ 的旧配置不会被关；旧开发版已写 `bili:{enabled:true}` 也不会。
- 修复：用 schemaVersion/迁移记录 opt-in，不依赖 setupDone；升级前任何 Bili 配置先 `enabled:false`，面板显式打开。

### 3.3 聊天 / 会话 / 投递状态机

#### H-01 / P1：`force` 绕过 `dryRun`/`enabled`，试运行仍会真实发 QQ

- `hub.js:461-506` `transmit`：`if (force) {}` 后跳过 `!cfg.enabled` 和 `cfg.dryRun`；`onCommand` 用 `sendSegments(...,{force:true})`（`:1265-1277`）；模块 `sendSegments` 也能传 force。
- 影响：默认 `dryRun:true` 时主人发 `/help`、`/status` 等命令会真实发送；扩展可绕过试运行。
- 修复：`force` 只允许绕过 `enabled`，绝不绕过 `dryRun`；统一 `EffectPolicy(chatId,{force})` 放在 `transmit` 最前，hooks.send 之前也检查。

#### H-02 / P1：`agentFor` 档位/preset 变化只新建 session，不清理旧 session 映射/旧工具/旧 turnState

- `hub.js:244-249`：`entry.preset !== preset || entry.level !== level` → `sid=''`，直接 `createSession`；没有 `sessionToChat.delete(oldSid)`、`turnState.delete`、`unmount(oldSid)`、`storage.epochs.bump(chatId)`。
- 对比 `switchIdentity`（`:2128-2142`）和 `abandonChat`（`:2112-2125`）做了完整清理。
- 影响：旧 session 的 `chatOfSession` 仍返回旧 chatId；旧 `turn/end` 会 `running.delete(chatId)` 释放新会话；旧 `deliver` 的 epoch 未 bump，旧档位/旧人设回复可发到当前 QQ；旧 agent 的插件工具/context 未卸载，降级后仍可执行。
- 修复：统一 `SessionIdentity`（account+chatId+level+preset+persona+epoch+turnId）；任何变化走唯一 `switchSession`：bump epoch → cancel 旧 turn → unmount → archive → 删除 `sessionToChat/turnState`；`turn/end` 必须验 turnId/sessionId。

#### H-03 / P1：Scheduler `BUSY_MAX_MS=4min` 会在同一 chat 启动第二个并发回合

- `runtime/scheduler.js:10,33,107-121,140-143`：`isBusy` 只按 `busySince` 时间；超过 4 分钟 `pump` 直接 `busySince.set(now)` 并 `run` 新 batch；`busySince` 是 `Map<chatId>`，`turnEnded` 无 turnId。
- `hub.js:1506` `running` 是 `Set<chatId>`；`turn/end` 无条件 `running.delete(chatId)`（`:1070-1071`），`release` 无条件 `scheduler.turnEnded`（`:1777-1779`）。
- 影响：长模型/工具 >4 分钟时第二批启动；第一批迟到 `turn/end` 释放第二批 busy，混用 `st.requests/st.text`，导致重复发送、回复串台、请求状态错。
- 修复：去掉隐式 4 分钟“当结束”；用 `turnId` token：`pushToSession` 生成 turnId+AbortController，`turn/end` 必须匹配才释放；超时只能 abort 当前 turn 并产生显式失败/结束事件。

#### H-04 / P1：普通回复的 guarded outbox 批次重启后永不恢复，半截回复永久 pending

- `hub.js:578-590`：`sendItemsNow` 对 `shouldSend` 函数传 `requiresGuard:true`；`deliver` 正常路径总是传 `shouldSend`。
- `host.js:210`：登录成功后 `hub.recoverOutbox()` 无 `shouldSend`。
- `outbox.js:110-127` `claimBatch`：`if (!m.requiresGuard || shouldSend)`，没有 guard 就不 claim；`pending()`（`:161-163`）同样直接 false。
- 最小复现：`enqueue({requiresGuard:true})` 后 `recover({maxAgeMs:0})` 返回 `{stuck:0,stale:0,resumed:0}`，`summary.pending=1`。

## 6. 重构路线图（按收益/风险）

### Phase 0：1–2 天，先止血（P0）

1. **面板 API 鉴权/CSRF 中间件**：所有 `/aurabot/api/*`（含模块 prefix）统一 `panelAuth`（DSH connection admit + panel token/Origin/Host/content-type）；副作用只允许 POST；`/modules/tool` 默认 `as:'other'`，owner/full 显式重新鉴权。
2. **`force` 只绕过 `enabled`，不绕过 `dryRun`**：`transmit` 最前面统一 `EffectPolicy`；命令回复、模块 `sendSegments`、`sendVoiceFile` 全部走同一入口。
3. **修复 outbox 恢复**：sessionReply 类批次提供安全 guard（account/epoch/enabled/dryRun）；`recover` 对 guarded 批次给出 pending/canceled 明确状态；补一个崩溃恢复测试。
4. **修复 scheduler 4 分钟**：先移除 `BUSY_MAX_MS` 的“当结束”分支，改为显式 abort 当前 turn；`busySince` 按 turnId 清除。
5. **修复 agentFor 档位切换**：所有 identity 变化统一 `switchSession`（bump epoch、cancel、unmount、archive、delete maps）；`turn/end` 验 turnId/sessionId。

### Phase 1：3–5 天，配置与前端硬伤（P1）

1. 抽 `core/config-service.js`：defaults/normalize/schema/secrets/merge/revision；`/save` 加 `configRevision` CAS；`loadConfig` 解析失败备份+只读降级；section null 安全。
2. 前端统一保存：单 `commit(patch)`；全局 draft + 底部保存；Persona 草稿/发布独立但上报 dirty；模块/扩展不再直接 `/save`；保存期间暂停轮询、请求 seq/Abort。
3. 修 `TAB_KEYS` 精确到叶子路径；分组切换自动选首个可见页；localStorage tab 校验；模块关闭显示 `ModOff`/`keepPanel`。
4. 补 `bridge` UI、Voice 缺失字段、Bili ffmpeg、merge 高级参数；把 NewFeatures 的孤儿设置搬回功能页；删除重复 SpeakUp。

## 7. 验收与测试建议

### 7.1 当前基线

```bash
npm test                         # 1745 tests, 1738 pass, 4 fail, 3 skipped
node --check <每个 js 文件>       # 全部通过
```

4 个失败不是“产品已坏”的证据，但说明 CI 不是全绿；修复前先补 test isolation/平台条件 skip，避免掩盖真实回归。

### 7.2 必补回归（按 P0/P1）

1. **面板安全**：无 token 请求 `/save`/`/modules/tool` → 401/403；跨站 `text/plain` POST 不改变状态；GET `/snowluma/reset-password` → 405；`/modules/tool` 默认 `as:'other'` 不能执行 owner 工具。
2. **dryRun/force 矩阵**：`enabled=false/dryRun=true/force=true` × `sendText/sendSegments/sendVoiceFile`，断言 `onebot.call` 次数；`hooks.send` 前也检查。
3. **长回合不并发**：scheduler 假时钟推进 >4 分钟，第一轮未 `turnEnded`；断言不增加 dispatch；`turnEnded(turn1)` 不释放 turn2；回复与 request 对应。
4. **outbox 恢复**：`sending/pending` guarded 批次 + `recover()` 无 shouldSend；断言 pending 被安全恢复/取消，不永久 1。
5. **档位切换**：`ownerLevel full→social`，旧 turn 未结束；断言旧 `chatOfSession` 为空、旧 mounted 清空、旧 turn/end 不发送、旧 agent 工具不可执行。
6. **入站/dispatch 异常**：`media.register`/`requests.create` 抛错；断言消息进死信/重试，不只 duplicate return。
7. **群限流**：participation 关闭 + engaged；100 条群消息只按 `maxPerHour/cooldown` 回；`groupInterjects` 有写入。
8. **历史边界**：清空后写 boundary；`seedHistory/quotedOf/qq_chat_history` 不返回边界前消息。
9. **配置**：并发 `/save` 基于同一 revision，第二个 409；坏 JSON 启动备份+只读；`normalize({model:null})` 不崩溃；`ext` 禁用模块密码不泄漏。
10. **数据恢复**：真实启动后（search/bili/图片处理过）的 `aurabot.db` 可通过 `prepareRestore`；`memory_overrides` 不丢或报告 dropped；checkpoint watermark clamp。
11. **生图**：关闭 `imageGen.enabled` 后 `/imagegen/submit` 拒绝；非白名单 chatId 拒绝；任意 asset id 不能跨聊天读；provider 返回 `http://127.0.0.1` 被 SSRF 防护拒绝。
12. **前端**：每个页面修改每个字段后哪些 tab 亮脏点；分组切换自动选首个页；localStorage 隐藏 tab 回退；保存期间输入不丢。

### 7.3 性能基准

- 用 10 万条消息/5000 事实的临时库，测 `/state`、`/memories`、`/learning/items`、`/diagnostics/*` 的 P95；目标：面板打开不阻塞消息处理。
- 记录 `eventLoopDelay`（diagnostics 已有 histogram）在 5 秒轮询 + 群消息并发下的 p95；超过 50ms 就应拆查询/移 worker。
